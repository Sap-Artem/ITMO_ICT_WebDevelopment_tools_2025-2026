# Лабораторная работа №3

## Цель работы

Цель лабораторной работы — контейнеризировать разработанное ранее приложение, настроить взаимодействие между несколькими сервисами с помощью Docker Compose, а также реализовать синхронный и асинхронный вызов парсера данных.

В работе используются результаты предыдущих лабораторных работ:

* FastAPI-приложение и база данных из лабораторной работы №1;
* парсер данных из лабораторной работы №2.

---

## Используемые технологии

| Технология         | Назначение               |
| ------------------ | ------------------------ |
| FastAPI            | REST API приложения      |

| Redis              | Брокер сообщений         |
| Celery             | Фоновое выполнение задач |

## Архитектура решения

После контейнеризации взаимодействие сервисов выглядит следующим образом:

```text
Клиент
  ↓
FastAPI
  ├── /parser/sync
  │         ↓
  │    Parser API
  │         ↓
  │    PostgreSQL
  │
  └── /parser/async
            ↓
          Redis
            ↓
      Celery Worker
            ↓
       PostgreSQL
```

Синхронный режим используется для немедленного получения результата парсинга, а асинхронный позволяет выполнять обработку в фоне без блокировки основного приложения.

## Вывод

В ходе выполнения лабораторной работы монолитное приложение было преобразовано в набор взаимодействующих контейнеров. Использование Docker Compose позволило централизованно управлять всеми сервисами проекта, а разделение функциональности между FastAPI, отдельным сервисом парсинга, Redis и Celery приблизило архитектуру системы к подходам, используемым в реальных production-проектах.

Дополнительно были реализованы два варианта запуска парсинга: синхронный через HTTP-запрос и асинхронный через очередь задач. Это позволило продемонстрировать преимущества фоновой обработки длительных операций и познакомиться с базовыми принципами построения распределённых сервисов.
